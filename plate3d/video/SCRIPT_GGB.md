## 6. 가설 시퀀스 — 어떻게 찍나

86장의 워크북을 차례로 불러오고, 로드마다 **같은 카메라로 다시 조준**합니다.
각 프레임은 연출이 아니라 **엔진이 진짜 시트에서 지은 진짜 모델**입니다.

```
node video/tools/make_ggb_stages.js        # 86장, 약 2.6 MB, 1분
```

| 구간 | 파일 | 장수 |
|---|---|---|
| 주탑 | `GGB_00_towers` | 1 |
| 케이블 | `GGB_01_cables` | 1 |
| 행어 | `GGB_02_ropes` | 1 |
| 트러스 | `GGB_03_truss_01…41` | 41 |
| 바닥판 | `GGB_04_deck_01…41` | 41 |
| 완성 | `GGB_05_done` | 1 |

생성기는 `tools/make_ggb.js` 를 스위치 두 개로 부릅니다 — **모델도 하나,
생성기도 하나**입니다.

| 스위치 | 뜻 |
|---|---|
| `PARTS=twr,mcb,hgr,trs,dk` | 어느 조립체를 배치할지. 배치 안 된 모듈은 정의만 되고 안 그려진다 — 엔진의 규칙 그대로 |
| `STAGE=<트러스>,<바닥판>` | 주탑에서 얼마나 나갔는지, 0~1 |

**한 경간은 그것과 주탑 사이의 경간들이 다 선 뒤에야 존재합니다.** 이게
`STAGE` 가 하는 일의 전부이고, 예뻐 보이려는 규칙이 아닙니다 — 매달 것이 없는
곳에는 딛고 설 것도 없으므로, 중앙에서 바깥으로 자라는 시퀀스는 아무도 지어 본
적 없는 것의 그림입니다.

두 스위치를 다 비우면 **출하되는 워크북과 행 내용이 완전히 같습니다.**
`tools/_rowdump.js` 로 414행을 대조해 확인했습니다.

**41 이 프레임 수인 이유**는 주경간이 82경간이고 두 주탑에서 자라기 때문입니다 —
한 프레임에 정확히 한 경간씩, 41번이면 중앙에서 만납니다. 더 달라고 하면 옆
프레임과 똑같은 파일이 나오고, 덜 달라고 하면 두 경간씩 건너뜁니다. **잘게
써는 단위를 편집자가 아니라 구조물이 정합니다.**

확인한 것:

```
86장 중 서로 다른 것 86장, 중복 0
GGB_03_truss_12.xlsx   modules 4 · assy 4 → placed 1102 · 겹침 0
```

## 7. 카메라와 촬영

촬영 하네스(`video_page.html`)가 카메라를 통째로 내줍니다 — `__aim(tx,ty,tz,
dist,az,el)` 로 **어디에 서서 어디를 볼지**를 밀리미터와 도로 지정하고,
`__grab()` 으로 캔버스에서 바로 프레임을 읽습니다(스크린샷보다 2.5배 빠름).

**그래서 "View 버튼을 누르지 마세요" 에 기대지 않습니다.** 앞 영상들은 엔진이
로드마다 화면을 다시 맞추는 것을 피하려고 버튼을 안 누르는 방식으로 버텼는데,
여기서는 **로드가 끝날 때마다 같은 값으로 다시 조준**하면 됩니다. 86장이
한 프레임도 어긋나지 않습니다.

시작값입니다. 촬영하며 다듬을 것이고, 각도는 +X 에서 잰 방위(`az`)라 다리가
X 축을 따르므로 **`az 90` 이 정면 입면**입니다.

**2 번 — 전체가 들어오는 ISO.** 엔진 자체 `iso` 방향(`0.58, −0.65, 0.5`)이
`az −48 · el 30` 인데, 2.3 km 짜리 물건에는 그게 너무 정직한 45° 라 다리가
화면을 대각선으로 가로지르며 양 끝이 잘립니다. `az −62` 로 눕히면 길이가
화면 가로에 더 실리고(투영 계수 0.74 → 0.88), `el 19` 로 낮추면 바닥 격자가
줄어듭니다. **앵커리지로 들어가는 백스테이 양쪽 끝까지 프레임 안에 있습니다.**

처음 적었던 `dist 2,400,000 · el 16 · az 78` 은 틀렸습니다 — 다리가 구석에
작게 앉고 격자만 넓었습니다. **멀리서 위에서 보면 2.3 km 짜리 납작한 물건은
선 하나가 됩니다.**

**11 번 — 주탑 히어로.** `el −4` 로 카메라가 타깃보다 아래에 서서 올려다봅니다.
주탑이 화면 가운데 서고 케이블이 양쪽으로 흘러나가며, 트러스와 바닥판이
아래를 가로지르고, 포털 스트럿과 다리 사이로 지나가는 노면이 다 보입니다.
`dist 300,000` 은 바닥판이 잘려서 360,000 으로 물렀습니다.

**6–10 번의 카메라가 고정인 것이 이 영상의 전부입니다.** 자라는 것이 컷의
내용인데 카메라가 움직이면 무엇이 자라는 것인지 알 수 없습니다. `az 85` 는
순수 입면(90)에서 5° 튼 값입니다 — 완전한 옆모습이면 두 트러스가 겹쳐 한
줄로 보이고, 살짝 틀면 바닥판이 폭을 가진 것으로 읽힙니다. 더 틀면(78) 다리가
비스듬해져 어디까지 놓였는지가 안 읽힙니다.

**11 번만 예외로 움직입니다.** 다 지었으니 이제 봐도 됩니다.

**3–5 번의 줌은 미리보기의 실제 휠 줌입니다.** 특히 5 번은 케이블이 직선
마디로 갈라져 보이는 배율까지 들어가야 자막이 참이 됩니다 — 안 갈라지면
자막을 빼는 편이 낫습니다.

**12 번 DXF 는 앱이 실제로 내보낸 파일을 `tools/dxf2svg.js` 로 그립니다.**
다시 조판하지 않습니다 — `video/README.md` 의 첫 규칙입니다.

**12 번의 첫 판은 프레임이 텅 비었습니다.** 두 가지가 겹쳤습니다. 페이지가
svg 에 제 크기를 정하게 뒀더니(`width:100%; height:auto`) 가로로 긴 창은
1080 px 페이지 맨 위에 120 px 짜리 띠로 그려졌고 — **중앙부가 빈 것이 아니라
중앙부가 없었습니다** — 창을 시트 높이의 분수(`[0,0.16]` 따위)로 잡았으니
3,785,154 단위짜리 종이의 아무 데나 짚었습니다. 지금은 페이지가 1920×1080 에
고정이고 `prep_ggb.js` 가 **도면마다 실제 잉크의 범위를 재서** 프레임을
줍니다.

**주행 컷은 트러스가 아니라 일반도입니다.** 처음엔 보강트러스 입면을
따라가려 했는데, DXF 는 선 굵기를 **시트 기준**으로 정하므로 1:5000 에서
현재 선 하나가 트러스 깊이의 28 % 입니다 — 아무리 당겨도 격자가 되지 않고
빗금 친 막대가 됩니다. 일반도는 2 km 에 340 m 라 프레임 높이로 잡으면
**주탑, 거기서 흘러나가는 케이블, 셀 수 있는 행어, 경간 중앙**이 차례로
지나갑니다. "두 킬로미터가 한 장에" 를 말이 아니라 화면으로 하는 것이
이 컷입니다.

**아홉 중 둘은 시트에서도 실제로 비어 있습니다.** `VIEW md.twr FRONT` 와
`VIEW md.twr TOP` 은 모듈이 **놓인 자리마다** 그리므로, 1:500 으로 주탑 둘을
1,280 m 떨어뜨려 그립니다 — 주탑, 1 km 의 공기, 주탑. 영상에서는 잉크를
x 로 뭉쳐 보고 **빈 구간이 도면 높이의 2.5배를 넘으면 갈라서** 한 기만
잡습니다. 출하 워크북은 건드리지 않았습니다 — VIEW 가 배치를 고르는 방식을
바꾸는 일이라 영상과 따로 판단할 문제입니다.

**색은 시트가 아니라 클릭입니다.** International Orange 로 찍되, 시트에서 색을
정하는 것처럼 보이게 하면 안 됩니다(§9).

## 9. 이 영상이 하지 않는 것

**"숫자 하나를 바꾼다"를 하지 않습니다.** TOWER 의 주장이고, 이 워크북은 아직
못 받칩니다 — GGB 에는 PARAM 앞장이 없고 주경간·새그·행어 간격은
`tools/make_ggb.js` 안의 상수라 **시트에서 고칠 수 있는 칸이 아닙니다.**
시트를 고치는 것처럼 찍으면 영상이 딱 한 가지에 대해 거짓말을 하게 됩니다.
하려면 PARAM 탭을 먼저 붙여야 합니다 — **2편의 재료**입니다.

**중량을 실물과 비교하지 않습니다.** 81,624 t 은 이 모델의 값입니다. 주케이블을
Ø920 중실봉으로 잡았으므로 실제 27,572 가닥의 강재 단면보다 약 20% 큽니다
(공표 직경은 감은 바깥 지름). 숫자는 내되 "실제 다리가 이만큼"이라고 하지
않습니다.

**색을 시트의 기능으로 보이게 하지 않습니다.** PLATE3D 는 색을 팔레트에서
자동 배정하고, 바꾸는 곳은 좌측 목록의 스와치 하나뿐이며, 그 선택은 파일에
남지 않습니다.

**앵커리지·교대·측면 브레이싱은 모델에 없습니다.** 화면에 안 나오므로 언급도
하지 않습니다. 케이블이 앵커리지로 들어가는 백스테이는 있습니다.

## 10. 정해진 것 / 확정 대기

정해진 것:

- 3–5 번(적는 것)과 9–10 번(자라는 것)이 같은 순서로 짝을 이룬다
- 트러스·바닥판은 **주탑에서 바깥으로만** 자란다
- 11·15 번에 자막을 넣지 않는다
- 시리즈 예고를 하지 않는다 — 2편이 만들어지기 전까지 약속하지 않는다
- 제목이 **BY PLATE3D** 로 열고 마지막 카드가 **와서 하나 지어 봐라**로 닫는다
- 끝에 입력 시트 414행을 통째로 훑는다 — 만든 것을 보였으면 만든 재료도 보인다

확정 대기:

- 공개 여부
- 주탑 입면·평면 두 장이 시트에서 반쯤 비는 문제 (VIEW 가 배치를 고르는 방식)

정해진 것에서 뺀 질문:

- ~~자막 언어~~ → **영어**. 앞의 다섯 편과 같습니다
- ~~9–10 번 길이~~ → **각 16초, 41프레임.** 프레임 수는 구조물이 정합니다(§6)
- ~~11 번 히어로 각도~~ → **`640080,0,165000 · 360,000 · az 55 · el −4`.** 잡아 봤습니다
- ~~2 번 조감도~~ → **ISO `0,0,98000 · 1,950,000 · az −62 · el 19`.** 전장이 다 들어옵니다
- ~~썸네일 문구~~ → **`THREE SECTIONS` / `2,219 MEMBERS`.** 그림이 골든게이트라고
  말하므로 글자는 그걸 되풀이하지 않습니다 — 바로 밑에 붙는 유투브 제목과도
  겹치지 않습니다(`mkthumb.js` 의 규칙)

## 11. 필요한 파일

```
plate3d/PLATE3D_GGB.xlsx                 모델 (Example 메뉴에 있음)
plate3d/tools/make_ggb.js                생성기 — PARTS · STAGE 스위치
plate3d/video/tools/make_ggb_stages.js   86장 시퀀스
plate3d/video/tools/aim_ggb.js           카메라 값을 눈으로 고르는 도구
plate3d/video/ggb/                       생성물 — 저장소에 넣지 않음
```

촬영 도구:

```
video/tools/prep_ggb.js          워크북 86장 + DXF + 도면 페이지·프레임 + 입력 시트 페이지
video/tools/mkcards_ggb.js       자막·타이틀·아웃트로 카드
video/tools/rendercards_ggb.js   카드 → PNG / JPEG
video/tools/shoot_ggb.js         촬영 — 86장 로드 + __aim 카메라, 17컷
video/tools/assemble_ggb.js      조립
video/tools/mkparampage.js       입력 시트를 시트로 그림 (FITW 모드)
video/tools/mkthumb.js           썸네일 — `node mkthumb.js ggb`
```

TOWER·SPLICE 와 달리 **값을 바꾸는 컷이 없어** 셀 카드(`mkcellcards.js`)가
필요 없습니다.

`mkparampage.js` 에 `FITW` 를 붙였습니다 — **폭에 맞추고 높이는 두는** 모드라
414행을 1080 px 안에 뭉개는 대신 읽는 크기로 팬할 수 있습니다. 기본값은
그대로여서 TOWER·SPLICE·BASIC 이 쓰는 페이지는 한 픽셀도 안 움직입니다.
