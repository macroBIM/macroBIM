# 교각(Pier) 입력체계 초안 — retaining-wall 형식 기반

> 원자료: AROAD `AAbutPierUserManual` §3.2 단면도 제원 (`apier.pdf`, 11p)
> 목표: 기존 옹벽 모듈(`bim_lwall.js` / `bim_invtwall.js` / `bim_gravitywall.js`)의
> `VARS = [[name, default, desc, tag]]` 입력체계를 그대로 확장하여 교각을
> **코핑(두부보) → 기둥 → 기초**까지 하나의 파라메트릭 단면(정면도)으로 입력받는 체계.

---

## 0. 기존 옹벽 입력체계 요약 (그대로 계승)

각 옹벽 모듈은 아래 한 가지 규칙만으로 입력 UI·라이브 SVG·CSV 일괄입력·DXF 출력을 모두 구동한다.

```js
// [name, default, description, colour-tag]   (단위: 특별표기 없으면 mm)
var VARS = [
  ["Hs", 4050, "Stem height",             "d"],
  ["N",   1.5, "Backfill slope 1:N",      "s"],
  ["tbl", 100, "Blinding thickness",      "f"],
  ["q",   1.0, "Surcharge q (t/m²)",      "o"],
  ...
];
```

| tag | 의미(옹벽) | 교각에서의 확장 의미 |
|-----|-----------|----------------------|
| `d` | 콘크리트 치수(dimension) | 콘크리트 본체 치수 |
| `s` | 지반/경사(soil·slope) | 경사·라운드·연단 처리 |
| `f` | 기초/버림(foundation) | 기초·버림콘크리트 |
| `o` | 하중 등 기타(other) | 옵션·하중·표시전용 |

**규칙**
- 값은 `VARS` 순서대로 위→아래(부재 상단→하단) 나열 → 그대로 CSV 일괄입력 순서.
- 스칼라 단면 1개를 그린다(정면도 1매). 라이브 리드로우 + 스크롤 줌/드래그 팬 + DXF out.

교각은 옹벽과 달리 **다중 기둥·다중 기초·단차 배열·탭 구조**를 가지므로,
아래 §3에서 위 포맷을 최소 확장한다.

## 1. PDF 검토 요약 — 교각 입력 구조

교각 입력은 상단 **[타입 설정 Wizard]** 로 형식을 고르고(입력 제원 범위가 형식에 따라 가변),
좌측 정면도 + 하단 **탭 10종**으로 제원을 넣는 구조.

### 1-1. 교각 형식 (Type wizard)
`T형 · 다주식 · 벽식 · 기둥식 · 문형 · 횃불형`
- T형: 기둥 1개.
- 다주식/기둥식: 기둥 2개 이상 → 기둥수·기둥간 거리(CL) 입력해야 정면도 반영.

### 1-2. 전역 옵션 (체크박스)
| 옵션 | 설명 | 영향 |
|------|------|------|
| 두부보 종방향 변단면 | 전후열 받침 있는 연결부 교각 | 두부보 후열(변단면) 제원·배근 **추가 입력** → §2-3 활성 |
| 기둥별 기초 적용 | 다주식에서 기둥별 기초 분리 | 기초를 기둥마다 개별 |
| 기초별 형식·제원 적용 | 기둥별 기초의 형식·제원을 별도 | 기초 탭이 구분 1..n 테이블 |
| 교축방향 코핑 확대 | 코핑폭 > 기둥일 때 변단면 확대 | 두부보 하부 형상 |
| 두부보 외측두께 일정 | 우측 캔틸레버 두께 = 좌측 | 우측 제원 자동 미러 |
| HRL 자동계산 | 횃불형 기둥상단→두부보 Round 자동 | HRL 입력 무시 |
| 지반선 표시 | 지반정보(BH-x) 출력, 기둥높이 실제높이 | 표시 + 기둥높이 해석 |

### 1-3. 하단 탭 10종 (= 부재 그룹, 상단→하단 순)
1) 두부보  2) 단차  3) 단차(변단면)  4) 기둥  5) 기둥단면
6) 기둥홈파기  7) 기초  8) 기초회전  9) 전차선받침  10) 측면벽

## 2. 변수 사전 — 코핑에서 기초까지 (그룹별)

> 접두 tag: `c`=두부보, `t`=단차, `k`=기둥, `f`=기초, `e`=부속(전차선받침), `w`=측면벽, `o`=옵션.
> 값 단위는 mm(각도 deg, EL은 m, 하중 t/m² 별도표기).

### 2-1. 두부보 (Coping / Cap-beam) — tag `c`
정면도 그리드 컬럼: `TL TB THL THU HLL HLR HRL HRR HEL HER HLU HRU CR HD HW HS`

| 변수 | 기본값 | 설명 |
|------|-------|------|
| `TL`  | 20000 | 두부보 길이(교축직각방향 전장) |
| `TB`  | 4000  | 두부보 폭원(교축방향) |
| `THL` | 1250  | 내민보 헌치부 두께 |
| `THU` | 1250  | 내민보 외측(선단) 두께 |
| `HLL` | 3250  | 좌측 내민보 헌치길이 |
| `HLR` | 3250  | 우측 내민보 헌치길이 |
| `HRL` | 0     | 두부보 하단 곡선 반지름(외측) — *HRL 자동계산 시 무시* |
| `HRR` | 0     | 두부보 하단 곡선 반지름(내측 지간부) |
| `HEL` | 0     | 좌측 캔틸레버 선단 수평처리 길이 |
| `HER` | 0     | 우측 캔틸레버 선단 수평처리 길이 |
| `HLU` | 0     | 두부보 좌측 외측연단 경사 설정값 |
| `HRU` | 0     | 두부보 우측 외측연단 경사 설정값 |
| `CR`  | 0     | 두부보 외측연단 라운드 |
| `HD`  | 0     | 코핑 중앙부 홈파기 깊이 |
| `HW`  | 0     | 코핑 중앙부 홈파기 폭 |
| `HS`  | 0     | 코핑 중앙부 홈파기 간격/설정값 |

*종방향 변단면(옵션) 시 후열 두부보용 `CTW`, `CTH` 추가.*

### 2-2. 단차 (Top step) — tag `t`  *[배열: 교좌면 단차수 n]*
| 변수 | 기본값 | 설명 |
|------|-------|------|
| `EL`   | 7.8196 | 좌측끝 두부보 상단 EL (m) |
| `nStep`| 4      | 교좌면 단차 수 |
| `DL[i]`| 2550…  | i번째 단차 거리(길이) — 좌→우 |
| `DH[i]`| -161   | i번째 단차 높이(+증가 / -감소) |
| `DA[i]`| true   | i번째 단차 적용여부 |

> ⚠ 단차 산정 전 **[권고안]** 버튼으로 거더하단 EL·형하공간 기준높이 반영 필요.

### 2-3. 단차(변단면 / 후열) — tag `t2`  *[옵션 “종방향 변단면” 시만]*
`DL2[i]`, `DH2[i]`, `DA2[i]` — 2-2와 동일 구조, 후열(변단면) 대상.

### 2-4. 기둥 (Column) — tag `k`  *[배열: 기둥수 nCol]*
| 변수 | 기본값 | 설명 |
|------|-------|------|
| `nCol` | 2    | 기둥 수(형식 종속: T형=1) |
| `CH[i]`| 8000 | i번째 기둥 높이 (기둥별 기초 시 기둥마다, 지반선 표시 시 실제높이) |
| `CL[i]`| 3375 / 6750 | 기초부 끝단→i번째 기둥 중심 거리 |

### 2-5. 기둥단면 (Column section) — tag `k`
| 변수 | 기본값 | 설명 |
|------|-------|------|
| `shape` | 원형 | 단면형상: 원형·사각형·트랙형·다각형 (enum) |
| `D`     | 2500 | 직경(원형) / 교축직각방향 폭(사각형) |
| `H`     | 0    | 교축방향 기둥 폭(사각형 등) |
| `sameUD`| true | 상하면 동일단면 — 해제 시 상/하 제원(`Du,Hu,Dl,Hl`) 별도 |
| `hollow`| false| 중공형 — 설정 시 외측/내측 제원(`Do,Di …`) 별도 |

### 2-6. 기둥홈파기 (Column groove) — tag `k2`  *[일반도 전용, 철근·수량 미반영]*
| 변수 | 기본값 | 설명 |
|------|-------|------|
| `g0,g90,g180,g270` | false | 홈파기 설치 위치(각도별 on/off) |
| `CB`,`CH_g`  | 0 | 0°/180° 홈파기 폭·높이 |
| `CB2`,`CH2`  | 0 | 90°/270° 홈파기 폭·높이 |

### 2-7. 기초 (Foundation) — tag `f`  *[배열: 기초수 nFdn, 기초별 형식·제원 옵션 시 구분 1..n]*
| 변수 | 기본값 | 설명 |
|------|-------|------|
| `type[j]` | 직접기초 | 형식: 직접기초·Mass기초·말뚝기초·단일현장타설말뚝기초 (enum) |
| `BH[j]`   | 2000 | 기초부 높이 |
| `BLF[j]`  | 2750 | 교축직각방향 기초연단→기둥끝단 거리(좌) |
| `BRF[j]`  | 2750 | 교축직각방향 기초연단→기둥끝단 거리(우) |
| `FF[j]`   | 2750 | 교축방향 기초연단→기둥끝단 거리(좌) |
| `FB[j]`   | 2750 | 교축방향 기초연단→기둥끝단 거리(우) |
| `slp[j]`  | 직각방향경사 | 경사방향(직각/교축방향경사, 도면 전용) |
| `SLW[j]`  | 0 | 교축방향 기초연단 경사부 폭(좌) |
| `SLH[j]`  | 0 | 경사부 높이(좌) |
| `SRW[j]`  | 0 | 경사부 폭(우) |
| `SRH[j]`  | 0 | 경사부 높이(우) |
| `EFL[j]`  | 100 | 버림콘크리트 기초돌출길이 |
| `EH[j]`   | 0 | 버림콘크리트 높이 |

> 단일현장타설말뚝은 기초별 형식 미지원 → 옵션 해제 후 형식 지정.

### 2-8. 기초회전 (Foundation rotation) — tag `f2`  *[다주식 미지원]*

## 3. retaining-wall 포맷으로의 매핑 전략

교각은 옹벽의 “단일 스칼라 단면”보다 복잡하므로, 기존 포맷을 **3가지만** 확장한다.

### 확장 ① 그룹(tag) 세분화 — 코드 변경 없음
옹벽의 `d/s/f/o` 4색을 §2의 `c/t/k/f/e/w/o` 로 늘리고, 입력폼에서
tag별 소제목(두부보/단차/기둥/기초/…)으로 구획만 그린다. `VARS` 구조 자체는 동일.

### 확장 ② enum·bool 값 타입 — 렌더러 소폭 확장
`VARS` 항목에 5번째 옵션 슬롯(선택형/체크형)을 허용:
```js
// [name, default, desc, tag, kind?]   kind: "num"(기본) | "bool" | ["원형","사각형","트랙형","다각형"]
["shape", "원형", "기둥 단면형상", "k", ["원형","사각형","트랙형","다각형"]],
["sameUD", true,  "상하면 동일단면", "k", "bool"],
```
`kind` 없으면 기존과 100% 동일(숫자 입력). 입력폼 렌더러만 bool→체크박스,
배열→select 로 분기.

### 확장 ③ 배열(테이블) 변수 — 접미 인덱스 전개
단차/기둥/기초처럼 개수가 가변인 항목은, 개수 변수(`nStep`,`nCol`,`nFdn`)를
먼저 두고 **개수만큼 인덱스 전개**하여 여전히 평면 `VARS`로 유지:
```js
function pierVARS(nStep, nCol, nFdn){
  var v = [ /* §2-1 두부보 스칼라들 */ ];
  v.push(["EL", 7.8196, "좌측끝 두부보 상단 EL", "t", "num"]);
  for (var i=1;i<=nStep;i++){
    v.push(["DL"+i, 2550, i+"번 단차 거리", "t"]);
    v.push(["DH"+i, -161, i+"번 단차 높이(+/-)", "t"]);
    v.push(["DA"+i, true,  i+"번 단차 적용", "t", "bool"]);
  }
  for (var c=1;c<=nCol;c++){
    v.push(["CH"+c, 8000, c+"번 기둥 높이", "k"]);
    v.push(["CL"+c, 3375, c+"번 기둥 중심거리", "k"]);
  }
  for (var j=1;j<=nFdn;j++){
    v.push(["BH"+j, 2000, j+"번 기초 높이", "f"]);
    // BLF/BRF/FF/FB/EFL … 동일 전개
  }
  return v;
}
```
- CSV 일괄입력 순서 = 전개된 `VARS` 순서(옹벽과 동일 UX 유지).
- 개수 변수는 tag `o`(옵션)로 폼 최상단에 노출, 변경 시 `VARS` 재생성 후 리드로우.

### 3-1. 신규 모듈 스켈레톤 `bim_pier.js` (T형·1기둥·1기초 baseline)
옹벽 모듈과 동일한 뼈대(`fdraw_pier(mountId)` → CSS/markup/initGW/draw + DXF).
아래는 형식 wizard 없이 **T형 기본형** 최소 `VARS`(배열 미전개, 스칼라만):

```js
var VARS = [
  // ── 옵션 ──
  ["TYPE","T형","교각 형식","o",["T형","다주식","벽식","기둥식","문형","횃불형"]],
  ["nCol", 1, "기둥 수", "o"],
  ["nFdn", 1, "기초 수", "o"],
  ["varSec", false, "두부보 종방향 변단면", "o", "bool"],
  ["copeWiden", false, "교축방향 코핑 확대", "o", "bool"],
  ["capOutEq", false, "두부보 외측두께 일정", "o", "bool"],
  ["hrlAuto", false, "HRL 자동계산(횃불형)", "o", "bool"],
  ["showGL", false, "지반선 표시", "o", "bool"],
  // ── 두부보(c) ──
  ["TL",20000,"두부보 길이","c"], ["TB",4000,"두부보 폭원","c"],
  ["THL",1250,"내민보 헌치부 두께","c"], ["THU",1250,"내민보 외측두께","c"],
  ["HLL",3250,"좌 헌치길이","c"], ["HLR",3250,"우 헌치길이","c"],
  ["HRL",0,"하단 곡선 R(외측)","c"], ["HRR",0,"하단 곡선 R(내측)","c"],
  ["HEL",0,"좌 캔틸레버 수평","c"], ["HER",0,"우 캔틸레버 수평","c"],
```

### 3-2. 그리기(정면도) 순서 — 옹벽 draw()와 동일 컨셉
좌표계는 옹벽처럼 **기초 하단을 기준**, 위로 적층:
1. 기초(BH) + 버림(EFL,EH) + 경사부(SLW/SLH,SRW/SRH)
2. 기둥 nCol개 — `CL[i]` 위치에 `shape/D/Hcol` 로 반복
3. 두부보 — `TB/THL/THU` 로 헌치, `HLL/HLR` 캔틸레버, `HRL/HRR` 라운드
4. 단차 — `EL` 기준 `DL/DH` 계단 상면
5. 부속 — 전차선받침·측면벽(좌/우 on일 때)
6. 옵션 — `showGL` 시 지반선, `hrlAuto` 시 HRL 역산

## 4. 열린 항목 (초안 검토 필요)

1. **형식 wizard 범위** — 6형식 전부 지원 vs. T형·다주식 우선. 형식별 활성 변수 표 필요.
2. **배열 UI** — 확장③(인덱스 전개) vs. 탭형 테이블 위젯 신설. 우선 전개 방식 제안.
3. **좌/우 미러** — `capOutEq`, 전차선받침·측면벽 좌우 구조. baseline은 단일값, 옵션 시 분리.
4. **HRL 자동계산·기초회전** — 도면 전용/계산 미반영 항목의 처리 위치.
5. **DXF/3D** — 옹벽처럼 DXF out + `bim_pier_3d.js` 후속 여부.
